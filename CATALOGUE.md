# Data & Supporting-Materials Catalogue

A complete inventory of what ships in this repository: the raw study data, the survey instruments, the cached model annotations (and the code that produced each), and the prompts / pre-registrations. Reproduction is **API-free** — the pipeline reads the committed files under `data/`; nothing here requires a key to render `results_methods.Rmd` (main-text Methods + Results) or `supplement/Bunkbot_SI.Rmd` (the **focal** Supplementary Information).

`Frozen` = a model annotation that needs paid API access to regenerate (shipped as measurement data). `Raw` = primary subject data. `Derived` = reproduced at render time.

**Compression.** Files that would exceed GitHub's 100 MiB per-file limit ship gzip-compressed (`.csv.gz` / `.jsonl.gz`). No reader change is needed on the R side (`readr`/base connections decompress transparently); the Python provenance scripts open them via `gzip.open`.

**De-identification.** The shipped data are de-identified: Qualtrics identity and geolocation columns (IP address, latitude/longitude, recipient name/email, external reference) are removed from every export, including the Study-4 merged telemetry file; the panel-vendor respondent ID (`rid`) is replaced everywhere by a salted-hash pseudonym (`anon_…`, consistent across files so duplicate-exclusion and cross-file joins are preserved; the salt is held privately by the authors); one participant free-text self-identification was redacted; and the panel-vendor callback token was redacted from the four QSF survey definitions. Qualtrics `ResponseId`s (`R_…`) are retained as the conversation key — they are internal Qualtrics identifiers not linkable without the researchers' account.

**Naming convention.** Every study-specific file is named `study{N}_{regime}_…`, where the regime is the human-readable condition label: **study1_jailbroken**, **study2_standard**, **study3_truth_constrained**, **study4_social_sharing**. Cross-study files say so in the name (e.g. `claim_role_labels_s1s3`, `claim_accuracy_pooled_s2_s4`).

> **Why the `processed_s1s3/` files are separate from the raw S1–3 exports.** The processed files carry **LLM-derived columns baked in** that the whole design depends on and that cannot be regenerated without paid API access. The raw `raw_qualtrics/study{1,2,3}_*` exports do **not** contain these, so the two are **not** redundant — the raw exports reconstruct the screening funnel (they include every entrant, including those screened out), while the processed files are the analytic input read by `build_s1s3()`. Study 4 has only a raw export; its processing happens through the cached sharing/stance pipeline (§3).

## 6. Provenance — the code that GENERATED the cached annotations — `code/provenance/`

Shipped read-only; **not** run by default reproduction (regenerating costs money). Every cached family in §3 traces to one of these (one file-level exception is noted below):

| Pipeline | Produces | Path |
|------------------------|------------------------|------------------------|
| **Conspiracy-topic taxonomy** | `topic_modeling/` embeddings + assignments (gemini-embedding-2 → PCA → HDBSCAN grid → 18 topics) | `code/provenance/conspiracy_topics/` (`pooled_conspiracy_topics.R`, `assemble_corpus.R`, tuning outputs) |
| **Fact-checking** | `claim_labels/`, `claim_datasets/`, `claim_veracity/` (extract → substantiveness → role → veracity via Perplexity sonar-pro); also `parse_*_ape_refusal.py` → S4 `compliance_ape/` | `code/provenance/python_api/claim_factcheck/` |
| **Focal-statement veracity** | `focal_veracity/` (per-conversation focal-statement scores + human-audit template/answer key under `output/provenance_work/`) | `code/provenance/python_api/focal_veracity/` |
| **5-rater post-stance v2** | `sharing_and_stance/` | `code/provenance/python_api/stance_v2/` |
| **Explanation-theme coding** | `explanation_coding/` | `code/provenance/python_api/explanation_coding/` |

> **APE note (S1–3):** the `evaluator_label`/`reverse_evaluator_label` columns were produced by the Attempt-to-Persuade-Evaluation harness (the `persuasion-main` conversation/eval engine), which was intentionally **excluded** from this repo (large, key-bearing). The **evaluator prompts** are documented in `prompts/base_v7_persuasion_degree.yaml`, the resulting labels ship under `data/api_cached/compliance_ape/`, and the S4 turn-0 parse (`parse_*_ape_refusal.py`) is included. The refusal-**type** analysis is `code/R/ext_nonattempt.R`.

> **Provenance scripts are repo-rooted (2026-06-24).** Each script resolves the repo root by walking up to the directory that holds `data/` and `code/`, then reads inputs from the new `data/` layout and writes the **shipped** products straight to their `data/api_cached/<family>/` homes under the new names; transient pipeline intermediates go to `output/provenance_work/<pipeline>/`.

The analysis engine itself is `code/bunkbot_helpers.R` + `code/R/` (numbers/figures/SI modules), driven by `code/R/build_all_numbers.R`.
